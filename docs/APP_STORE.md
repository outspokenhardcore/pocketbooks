# Shipping the PocketBooks app

> **Ready to submit?** Go straight to the [launch runbook](LAUNCH.md). This page
> is the background: lanes, review risks and listing copy.

PocketBooks is a client for **your own** server. That shapes every distribution
decision below: there is no hosted backend, no account system, and nothing to
sell. Pick the lane that matches who should get the app.

| Lane | Who it reaches | Apple Developer Program | Effort | Rebuild needed |
|---|---|---|---|---|
| **Personal device build** | You | Not required (free Apple ID) | Minutes | Every 7 days |
| **Ad Hoc / registered devices** | Up to 100 devices you register | Required ($99/yr) | Low | Yearly |
| **TestFlight** | Up to 10,000 testers by link | Required | Medium (review for external testers) | Every 90 days |
| **App Store** | Everyone | Required | High (full App Review) | On each update |

For a self-hosted tool, **TestFlight is the realistic destination**. The App
Store lane is documented too, including the parts reviewers reliably ask about.

## 0 · One-time project setup

> **Shipping your own build?** You may. The project is AGPL-3.0 with an
> [additional permission for app store distribution](../APP_STORE_EXCEPTION.md),
> which removes the usual friction between GPL-family licenses and the App
> Store's terms. You need your own Apple Developer account and a bundle
> identifier you own, you publish your source changes, and you link to the
> source from the listing or the app.

The Xcode project is generated from [`ios/project.yml`](../ios/project.yml) and
is not checked into Git. Before any distribution build:

1. **Claim a bundle identifier.** Replace the example
   `com.example.pocketbooks` with one that belongs to your account, for example
   `com.yourname.pocketbooks`. Register it under *Certificates, Identifiers &
   Profiles* in the Apple Developer portal.
2. **Regenerate and open the project.**

   ```bash
   brew install xcodegen
   cd ios
   xcodegen generate
   open PocketBooks.xcodeproj
   ```

3. **Select your team.** Target *PocketBooks* → *Signing & Capabilities* →
   your team, *Automatically manage signing*.
4. **Set the version.** `MARKETING_VERSION` and `CURRENT_PROJECT_VERSION` in
   `project.yml` drive `CFBundleShortVersionString` and `CFBundleVersion`.
   Bump the build number for every upload; App Store Connect rejects duplicates.

Verify before you archive:

```bash
cd ios
xcodebuild -project PocketBooks.xcodeproj -scheme PocketBooks \
  -destination 'generic/platform=iOS Simulator' build CODE_SIGNING_ALLOWED=NO
```

## 1 · Personal device build

The fastest path and enough for a private setup.

1. Sign in to Xcode with any Apple ID (*Settings → Accounts*).
2. Pick your iPhone as the run destination and press Run.
3. On the iPhone, trust the developer under
   *Settings → General → VPN & Device Management*.

A free account's provisioning expires after 7 days; just build again. Paid
accounts get a year.

## 2 · TestFlight

1. In App Store Connect, create a new iOS app record with your bundle
   identifier. Name, primary language, and SKU are required; the SKU is
   internal and never shown.
2. In Xcode: *Product → Archive*, then *Distribute App → TestFlight & App
   Store*.
3. **Internal testing** (up to 100 testers on your team) starts immediately
   after processing — no review.
4. **External testing** (public link, up to 10,000 testers) needs a short
   Beta App Review. Fill in the beta description and the review notes from
   [section 4](#4--what-reviewers-ask-about) — external beta review asks the
   same server questions as App Review.
5. Builds expire after 90 days. Upload a new build to keep the link alive.

Because testers need their own Mac server, put the setup requirement in the
beta description, not just in the review notes:

> PocketBooks plays audiobooks generated by the PocketBooks server, which you
> run yourself on an Apple Silicon Mac. Set up the server first — see
> github.com/outspokenhardcore/pocketbooks — then enter its address and token on the
> app's first screen.

## 3 · App Store submission checklist

Everything here is already prepared in the repository unless marked **you**.

| App Privacy answers | **you** — see below |
| Demo account / review notes | **you** — see below |

### Screenshots

App Store Connect needs one 6.9" iPhone set and one 13" iPad set. Both are
generated from the running app, against your own server, by a UI test that
navigates the real UI:

```bash
# with the backend running and `python -m app.samples` already done
PBS_URL=http://127.0.0.1:8725 PBS_TOKEN=<token from the server> ios/screenshots.sh
```

It boots each simulator, points the app at your server through the simulator's
preferences (so the token never appears in a test log), sets the status bar to
Apple's 9:41 marketing state, drives the app, and writes:

```text
ios/screenshots/iphone-16-pro-max/     1320 x 2868   (6.9")
ios/screenshots/ipad-pro-13-inch-m4/   2064 x 2752   (13")
    01-library.png            the library with covers, authors and runtimes
    02-voices.png             the six built-in voices
    03-player-generating.png  chapter 2 playing while chapter 6 does not exist yet
    04-transcript.png         the synchronised transcript, spoken line highlighted
    05-library-light.png      light theme with the "Continue" row
```

Re-run it after any UI change; the captures are defined in
[`ios/UITests/ScreenshotTests.swift`](../ios/UITests/ScreenshotTests.swift).

Two things to know. iOS redacts secure text fields in every screen capture, so
the settings screen with its token field photographs as an empty box — that is
why it is not in the set. And `03` and `04` legitimately show a short remaining
time, because only the already-generated part of the book is seekable; the
"Generating 97/627" label is what explains it.

### App Privacy ("Data Collection")

The client talks only to the server address you type in. It has no analytics,
no ad SDK, no crash reporter, and no third-party network calls. The honest
answer in App Store Connect is **"Data Not Collected"** for every category, and
**"No"** for tracking. Verify this yourself before you declare it: the only
outbound requests in [`APIClient.swift`](../ios/AudiobookApp/APIClient.swift)
and [`DownloadManager.swift`](../ios/AudiobookApp/DownloadManager.swift) go to
the configured base URL.

You still need a privacy policy URL. A one-page statement saying the app stores
the server URL, token, appearance setting, and listening positions on the
device and sends nothing anywhere else is sufficient and accurate.

### Age rating

No user-generated content, no web browsing, no ads. The content comes from the
books the user supplies, which is why the rating questionnaire should be
answered for the app itself, not for any particular book.

## 4 · What reviewers ask about

Three things about this app reliably come up. Answer them in the *Notes* field
up front instead of waiting for a rejection.

**1. "The app is unusable without a server."** This is Guideline 2.1 territory.
Give the reviewer a working setup or an honest explanation:

> PocketBooks is a player for a self-hosted audiobook server that the user runs
> on their own Mac. It is the client half of an open-source project
> (github.com/outspokenhardcore/pocketbooks, AGPL-3.0). There is no hosted service
> and no account.
>
> For review, a demo server is reachable at <URL> with token <TOKEN>. Enter
> both on the first screen and tap Connect. The library contains five
> public-domain books; open one and playback starts while the server is still
> generating audio.

Stand up that demo server before you submit. A reviewer with no server sees an
empty settings screen, which reads as a broken app.

**2. "Why does the app allow arbitrary loads?"** `NSAllowsArbitraryLoads` is
enabled because users reach their own Mac over plain HTTP on a LAN or a
Tailscale tailnet, where no public certificate can be issued. Say exactly that:

> The app connects only to a server address the user enters. Home servers and
> tailnet addresses cannot present a publicly trusted TLS certificate, so the
> ATS exception is required for the app to work at all. No other hosts are
> contacted.

If you run your server behind a TLS-terminating reverse proxy with a real
certificate, you can drop `NSAllowsArbitraryLoads` from `project.yml` and keep
only `NSAllowsLocalNetworking`. That is the cleaner submission, at the cost of
more setup for your users.

**3. "What about the content?"** The app ships no books. Users convert PDFs from
their own library, and the project's sample catalog contains public-domain
works only. Note that the app includes no store, no catalog browsing of
third-party content, and no DRM circumvention.

## 5 · Store listing copy you can start from

**Subtitle (30 chars):** `Your PDFs, read aloud`

**Promotional text:** Start listening while your Mac is still generating the
audiobook. No cloud, no account, no upload.

**Description:**

> PocketBooks is the iPhone player for your own PocketBooks server. Point it at
> the Mac on your network, pick a book from your library, and playback begins
> as soon as the first audio segments exist — you do not wait for the whole
> book to finish.
>
> • Browse the library on your own server
> • Start listening while generation is still running
> • Chapter list and chapter seeking
> • Listening position syncs across your devices
> • Download the finished audiobook for offline listening
> • Background playback with the screen locked
>
> Requires the free, open-source PocketBooks server on an Apple Silicon Mac.
> Your books never leave your own hardware.

**Keywords:** `audiobook,tts,self-hosted,pdf,player,offline,chapters,local`

Screenshots that convert well for this app: the library with covers, a book
playing with the progress bar mid-generation, the chapter list, and the
settings screen showing how little is needed to connect.

## 6 · Release checklist

```text
[ ] Bundle identifier replaced and registered
[ ] MARKETING_VERSION and CURRENT_PROJECT_VERSION bumped
[ ] xcodegen generate run after editing project.yml
[ ] Simulator build passes
[ ] Tested on a real iPhone against a real server
[ ] Background playback verified with the screen locked
[ ] Demo server running and reachable from outside your LAN
[ ] Review notes include server URL, token, and the ATS explanation
[ ] App Privacy answered as "Data Not Collected"
[ ] Privacy policy and support URLs live
[ ] Screenshots for every required device size
```

The backend is not distributed through any store. Users install it from this
repository; see the [README](../README.md) and
